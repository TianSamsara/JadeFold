# JadeFold · 凝影阁

**凝万千光影，藏于方寸之间。**

JadeFold（凝影阁）是白玉京系列的 Windows 本地离线视频压缩工具。以玉白、青黛、淡金与云海仙阙构成玄幻古风界面，使用 Electron + React + TypeScript + FFmpeg。

视频在本机处理，无需账号、无需上传。支持显卡编码加速、CPU + 显卡混合并行、批量队列、画质预设、实时进度、取消与失败重试，输出新文件并保留原视频。

## 使用

打包后双击 `release/白玉京-凝影阁-0.8.0-Windows.exe`。无需另外安装 FFmpeg。

1. 拖入视频，或点击「添加视频」（快捷键 Ctrl + O）。
2. 在页面中间选择用途：自动压缩、手动调画质、指定大小、快速压缩或兼容播放。切换用途自动应用推荐搭配。
3. 选择输出文件夹，在自动压缩下点击「分析并压缩」；软件先试压评分，合适才完整编码，缩不动则显示「已保留原片」。
4. 在右侧确认输出摘要，按需展开高级设置。小丸经典参考位于手动调画质和指定大小的更多设置中。

支持 MP4、MOV、MKV、AVI、WebM、M4V、WMV、FLV、TS、MTS、M2TS 输入，MP4 / MKV 输出。支持 NVIDIA NVENC、Intel Quick Sync、AMD AMF 显卡编码与 CPU 编码；启动时通过真实试编码检测支持，自动模式优先显卡，处理失败会提示并回退 CPU；支持 H.264 / H.265、批量顺序 / 混合并行队列、实时进度、取消、失败重试和最近 100 条处理记录。文件同名时自动编号，不修改输入文件。

## 开发

环境：Node.js 22.12+（建议 Node.js 24）、pnpm 11，Windows x64。

```powershell
git clone https://github.com/TianSamsara/JadeFold.git
cd JadeFold
pnpm install
pnpm dev
```

构建、验证和打包：

```powershell
pnpm build
pnpm test
pnpm test:desktop
pnpm dist
```

便携包生成在 `release/`。依赖、测试素材、构建产物和便携包均不提交到 Git 仓库。

本机 Codex 环境只有内置 Node / pnpm，使用项目里的 `dev.ps1`、`build.ps1` 或 `start.ps1`；脚本会寻找系统或 Codex 内置运行时。

GitHub 二进制下载不可达时，Electron 可设置 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`。FFmpeg 镜像下载与校验安装方法见 `scripts/setup-binaries.ps1`。运行软件时不需要网络。

浏览器模式 `pnpm dev:web` 仅供布局预览；本地文件处理需要 Electron 桌面版。

## 当前限制

- 手动模式处理第一路视频和第一路音频，不复制字幕、多音轨、章节和附件。智能模式遇到多音轨、字幕或附件会跳过。
- 暂不支持 HDR 色调映射、GPU 解码/缩放或暂停续传。
- 手动 CRF 模式不承诺固定压缩比例，输出可能更大；智能模式会检查完整结果的实际体积，未达到缩小目标不导出。
- 分辨率选项限制画面宽高边界，保持比例且不放大，竖屏以所选最高高度为限。
- 应用重启后保留完成记录与参数，不恢复未完成队列。取消会清理当前临时文件；系统断电或强制终止可能留下 `.jadefold-*` 临时目录（旧版为 `.frame-*.partial.*` 文件），可手动删除。
- 当前便携包为未签名的本地试用版。

设计与来源见 [docs/DESIGN.md](docs/DESIGN.md)、[docs/THIRD_PARTY.md](docs/THIRD_PARTY.md)。

## 显卡加速

在自动压缩、手动调画质、快速压缩或兼容播放中，右侧「用什么处理」直接选 CPU 或显卡。选择显卡后可自动挑选，或指定 NVIDIA / Intel / AMD。NVIDIA / Intel / AMD 的 H.264 与 H.265 支持分别检测；不支持的选项不可选择。自动优先顺序为 NVIDIA、Intel、AMD、CPU。显卡仅加速视频编码；解码、缩放和音频仍会使用 CPU。不同编码器的 CRF / CQ / ICQ / QP 数值不可直接比较，实际速度和体积取决于素材与设置。若手动选定的显卡处理失败，会保留失败信息供重试；仅自动模式回退 CPU。

## CPU + 显卡混合并行

在手动调画质、快速压缩或兼容播放中选择显卡，再开启「同时处理两个视频」。两个及以上待处理视频时，显卡和 CPU 各处理一个文件，每个工作线程完成后继续领取队列任务。最多同时处理两个视频；单个视频由一种视频编码器完成，不做分段拼接。只有一个视频或选择 CPU 编码时保持顺序处理。

混合模式将 CPU 编码线程限制在逻辑处理器数量的一半，最多 8 个；同时限制解码 / 缩放线程，为显卡任务与界面留出余量。编码器画质参数并不等价，不同文件可能得到不同大小和画质结果。自动模式的显卡任务失败会提示并改用 CPU；取消会停止所有正在处理的任务，尚未开始的视频保留在队列中。

该模式不监测显存或 GPU 利用率，也不按百分比分摊单个文件。并行不保证更快，解码、磁盘和功耗可能成为瓶颈。

## 精细压缩与小丸参考

v0.4.0 提供三类素材预设（日常、动漫、录屏）、CPU slow / slower / veryslow、H.265 10bit、原音轨复制、64–320 kbps AAC，以及目标体积二遍编码。v0.6.0 新用户默认使用智能均衡，已保存的设置保留。

「小丸经典参考」按公开旧版源码中的 x264 参数配置：veryslow、ref 3、bframes 3、UMH、scenecut 60、deblock 1:1、qcomp 0.5、psy-rd 0.3:0、AQ 2 / 0.8。使用随本应用打包的 libx264，不包含原小丸可执行文件，不能视为与所有小丸版本逐字节一致。

指定体积单位按 1 MB = 1024² 字节计算，预留音频和约 2% 封装空间。码率不足时会拒绝目标，而不是偷偷降分辨率或帧率。简单画面可能无法消耗完整码率，输出可能明显小于目标；复杂片源也不保证精确卡在目标大小。

小丸经典参考和指定大小仍固定使用 CPU；普通手动调画质可选 CPU 或显卡。10bit 不能恢复原视频丢失的信息，也不代表 HDR 色调映射。

质量与功能检查：

```powershell
pnpm test:quality
pnpm benchmark
# 使用自己的素材，取前 6 秒作短片分析
pnpm benchmark -- "D:/videos/input.mp4"
```

基线报告见 [docs/QUALITY.md](docs/QUALITY.md)。报告区分编码参数参考与真实原程序对照，不以降低分辨率或只看文件大小作为质量提升证据。

## 体积与播放诊断

v0.5.0 导入时读取源视频编码、标签和码率。H.265 转 H.264 会提示体积风险，H.265 输出会提示播放器兼容要求。单个待处理文件可按原片 85% 设置目标体积（CPU 二遍编码）；小于可设置下限的文件不显示该快捷按钮。

输出完成后重新读取实际编码、码率与大小。输出未缩小会显示黄色「转码完成」及原因提示，并保留文件，不作为绿色压缩收益展示。恒定画质模式本身没有大小保证。转换为更兼容的编码可能更大。

MP4 是容器，不代表每个播放器都能解码其中的 HEVC。Windows 自带播放器可能需要 HEVC 视频扩展；FFmpeg 可解码不等于系统播放器已有解码器。详见 [排查说明](docs/TROUBLESHOOTING.md)。运行 `pnpm test:diagnostics` 检查该流程。

## 自动压缩（v0.8.0）

先读取编码、视频/音频码率、像素格式、时长和轨道信息，再使用所选 CPU 或显卡对短片试压（slow 档）；短视频取一段，15 秒及以上视频在约 10%、50%、85% 处各取 3 秒。候选 CRF 为 18–32，先在中间片段搜索，再验证其他片段。保持原分辨率、帧率，复制原音轨，不通过静音或降分辨率获得体积收益。

默认「清晰且适中」要求每段的平均 VMAF 至少 93、低分位帧 VMAF 至少 85、平均 SSIM 至少 0.97（录屏为 0.985），并在视频码率加 10% 余量和计入音频/封装后，预计至少缩小 10%，才进行完整编码。完整结果实际缩小不足 5%，不发布临时成品，原片始终保留。评分失败、采样不可靠或无合格方案时跳过，不自动套用未经验证的参数。

默认 H.264 / HEVC 原片保持相同编码类别，其他受支持的 SDR 4:2:0 素材使用 H.264；可明确允许升级 H.265。H.265 原片不会默认降为 H.264。输出 H.265 仍需要能解码 HEVC 的播放器，本功能不会安装系统解码器。

自动压缩逐个处理视频，可选 CPU 或显卡。自动选择显卡试压不合适或完整编码失败时，重新用 CPU 试压评分，只有 CPU 自己的结果达标才继续。10bit 原片在自动选择设备时使用 CPU 保留色深；指定显卡则提示改选 CPU。HDR、隔行、特殊色度/高色深、多视频/多音轨/字幕/附件，以及无法可靠读取音频码率等输入会保留原片，交由手动模式处理。采样会额外耗时和使用临时磁盘空间。

这些是本版本采用的保守筛选门槛，不代表整片视觉无损，也不证明是全局最优参数。未抽中的复杂片段可能表现不同，重要素材应保留原片并人工检查。评分逐帧对齐，并检查参考和输出帧数；早期基线中存在的时间基准对齐问题及重测结果见 [QUALITY.md](docs/QUALITY.md)。运行 `pnpm test:smart` 检查完整桌面流程。

## v0.7.0 用途与搭配工作台

五个用途入口将自动试压、精细编码、体积预算、快速处理和播放兼容分开。右侧摘要显示视频、声音、执行方式和体积预期；高级设置按模式提供，切换用途自动清理冲突参数。兼容播放由后端限制为 MP4 / H.264 / AAC / 8bit。旧有效参数保留，历史页面不再显示待处理设置。

参考了 HandBrake、ab-av1、StaxRip、Other Video Transcoding、NotEnoughAV1Encodes、LosslessCut 的公开文档与设计。具体借鉴、取舍和模式搭配表见 [WORKFLOWS.md](docs/WORKFLOWS.md)。原有说明中的“快速 / 兼容转码”已拆为两个用途，旧“指定体积”改为独立的“指定大小”入口。

运行 `pnpm test:modes` 可验证切换、参数联动、兼容输出与窗口布局。


## v0.8.0 更直白的控制与记录管理

- 处理记录每行可单独删除，也可清空全部记录；仅修改列表，原视频和输出文件都保留，重启后删除仍生效。
- 画质三档：「尽量保留细节」「清晰且适中」「文件更小」。自动模式会改变试压的质量门槛；手动模式应用相应起始参数，并提供向右保留更多细节的滑块。这不是画质百分比，也不是锐化或修复。
- CPU 和显卡并列显示，说明速度与体积取舍；不再要求先理解 NVENC、CQ 或 ICQ 才能开始。
- 指定大小、小丸经典仍只支持 CPU；界面会说明限制。显卡选择按保存的视频编码检查，自动压缩按每个原片实际编码检查。
- `pnpm test:friendly` 检查实际显卡自动压缩、CPU 重新试压回退、画质控制、历史单条删除与重启持久化。
