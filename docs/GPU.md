# 显卡编码加速

v0.8.0 的右侧「用什么处理」直接选择 CPU 或显卡。自动压缩和手动调画质默认 CPU；快速压缩和兼容播放默认显卡优先。选择显卡后可指定 NVIDIA / Intel / AMD，或自动选择。指定大小与小丸经典仍只支持 CPU。

启动后使用内置 FFmpeg 对每个后端、每种视频编码做真实短片试编码。不以 Windows 显卡名称或 FFmpeg 编译列表直接认定可用。自动按 NVIDIA、Intel、AMD、CPU 顺序选取当前 H.264 / H.265 的可用编码器。手动选定不可用后端时不启动任务；自动模式的硬件编码失败会清理当前临时文件、显示原因并从头改用 CPU。

| 后端 | 实际编码器 | 画质控制 | 速度映射 |
| --- | --- | --- | --- |
| CPU | libx264 / libx265 | CRF | fast / medium / slow |
| NVIDIA | h264_nvenc / hevc_nvenc | VBR + CQ，目标码率为 0 | p3 / p5 / p7 |
| Intel | h264_qsv / hevc_qsv | global_quality（ICQ） | fast / medium / slow |
| AMD | h264_amf / hevc_amf | CQP，I/P 帧 QP；H.264 另设 B 帧 QP | speed / balanced / quality |

手动画质滑块向右表示更多细节，内部映射到 35–18（0.5 步长），不把这个值显示为画质百分比；不同编码器不等价。显卡编码通常以更低的 CPU 编码负担完成工作，但实际速度受素材、驱动、视频解码、分辨率和磁盘影响。本版本视频解码与缩放、音频编码仍在 CPU 上执行。

实现参数通过随软件打包的 FFmpeg 6.1.1 的 `-h encoder=h264_nvenc`、`-h encoder=h264_qsv`、`-h encoder=h264_amf` 帮助核对。NVIDIA 官方 FFmpeg 使用文档：https://docs.nvidia.com/video-technologies/video-codec-sdk/13.0/ffmpeg-with-nvidia-gpu/index.html 。本机测试详情见 TESTING.md。

## v0.3.0 混合并行

在手动调画质、快速压缩或兼容播放中开启「同时处理两个视频」后，当队列至少有两个视频且存在所选可用显卡时，启动一个显卡工作任务和一个 CPU 工作任务，各自领取完整文件。最大同时运行数为 2；单文件不拆分。CPU 编码最多使用逻辑处理器数的一半、上限 8 个线程，x265 另限制线程池；解码和缩放也设置线程预算。

自动模式的显卡任务失败可回退 CPU，此时两个任务都可能使用 CPU；状态按实际编码器显示。取消会向两个编码进程发送停止信号，等待清理完成后结束队列。尚未开始的任务仍可继续处理。历史记录串行落盘，避免并行完成时覆盖记录。

这是一种按文件分配的批量并行方式，不采样 GPU 负载或显存，不按资源利用率迁移正在编码的文件。混合输出使用各自编码器的画质控制，不能保证跨编码器视觉效果和体积完全一致。


## 自动压缩与显卡

自动压缩也可选择显卡。试压和完整编码按每个视频实际输出的 H.264 / H.265 选择设备，并使用同一编码器和设置。画质评分仍使用 CPU。自动选择显卡不合适时重新用 CPU 试压，不直接沿用显卡质量值；取消操作不会触发回退。指定显卡失败时保留原片和原因。

当前显卡自动试压只支持 8bit；10bit 原片在自动选择时改用 CPU 保留色深，手动指定显卡时跳过并解释。自动压缩按文件顺序执行，不提供双文件混合并行。
