# v0.8.0 易用性与设备选择验证

日期：2026-11-09，Windows x64，Node.js 24。

新增画质偏好、CPU / GPU 选择、单条处理记录删除。自动试压按实际设备输出评分，原有帧对齐和输出体积保护不变。测试素材均在本机合成，用户视频未加入仓库或包内。

`pnpm test` 共 37 项检查（含硬件子项）：新增设备选择与迁移、三个画质门槛的行为、原片编码匹配和 10bit 显卡保护，以及实际 NVENC / QSV 在 H.264 / H.265 下的试压和完整输出。测试文件串行执行，避免多个测试进程同时争用显卡；首次并发测试曾出现一次 QSV 试压失败，串行实测通过。本机无 AMD 可用编码设备，未验证 AMD 实机结果。

严格细节档的 640 × 360 / 24fps / 2 秒 FFV1 合成样本结果，仅用于验证功能链条：

| 设备 / 输出编码 | VMAF | SSIM | 输出字节 |
| --- | ---: | ---: | ---: |
| NVENC / H.264 | 96.51 | 0.98980 | 125,592 |
| NVENC / H.265 | 95.80 | 0.98962 | 111,262 |
| QSV / H.264 | 96.38 | 0.99246 | 151,072 |
| QSV / H.265 | 95.90 | 0.98988 | 120,849 |

四种结果均保留原尺寸和 48 帧，达到当前细节门槛和体积保护要求。不是同画质性能排名，也不代表真实素材的压缩比例。

七条源码桌面流程覆盖原有压缩、混合队列、两遍体积、扩容诊断、CPU 自动试压、模式切换，以及新的 `pnpm test:friendly`。新流程验证：

- 画质三档和滑块方向正确，设备选择在刷新后保留；指定大小和经典方案不能选择显卡。
- 实际 NVENC 自动压缩，96 × 96 样本触发显卡限制后 CPU 重新试压评分。
- 在测试进程中注入一次完整输出阶段错误，确认重新进行 CPU 评分再完成输出；样本 GPU 选中 32、CPU 重新选中 28，没有直接复用数值。该故障注入仅在测试脚本，不在产品内提供开关。
- 分别删除已完成、保留原片的记录，检查队列、原文件和输出文件未被删除；重启后删除仍生效；清空记录也保留文件。
- 390 / 960 / 1440 宽度布局无水平溢出，画质、设备、记录状态截图人工查看。

打包验证使用 `FRAME_PACKAGED_EXE` 指向 `release/win-unpacked/白玉京·凝影阁.exe`，运行 friendly 与 smart 流程；内置 FFmpeg / FFprobe / VMAF 和记录持久化一起检查。

## v0.2.0 显卡编码验证

本机显卡：NVIDIA GeForce RTX 5060 Laptop GPU、Intel Graphics。应用以 256 × 256 的短片分别试编码，NVIDIA NVENC 与 Intel Quick Sync 的 H.264 / H.265 均可用；AMD AMF 因本机没有可用 AMD 驱动而禁用，未实机验证 AMD 输出。

桌面端验证默认「自动」实际选择 NVENC，输出文件可探测、时长正确且文件存在；手动切换 CPU 也成功。相同合成样本在 NVENC CQ 26 下输出 359,158 字节，在 CPU CRF 26 下输出 254,389 字节。CQ 和 CRF 数值不等价，该结果不用于证明相同画质或速度提升倍数。

另外导入 32 × 32 视频，触发 NVENC 的最小画幅限制，验证自动模式先失败再切换 CPU、界面显示回退原因、最终输出成功且无临时残留。这验证了“驱动可用但某个输入不兼容”的真实回退路径。

## v0.3.0 混合队列验证

## v0.6.0 智能均衡验证

新增 8 项检查：长视频多点采样、不采用低画质或未完整验证的候选、HDR / 特殊色度 / 多音轨等保留原片、跨容器逐帧对齐无损校验、真实试压选参与体积保护、紧凑 HEVC 跳过、完整输出更大时不发布成品、分析取消后的临时文件清理。原有 21 项测试继续通过。

`pnpm test:smart` 桌面测试使用本地合成的 18 秒高码率 H.264 + AAC 和 2 秒紧凑 HEVC。前者自动取三段、选中 H.264 slow CRF 28，输出 1,265,206 字节，原片 8,843,662 字节；三段最低平均 VMAF 94.953、SSIM 0.988039，保留 640 × 360 / 24 fps，原音轨压缩流逐字节相同。后者显示「已保留原片」，没有新成品；取消分析可清理临时目录。处理记录持久化、查看原片、重试和重启后从历史重新加入队列均已检查。比例仅适用于该合成素材。

完整源码桌面回归还包含 GPU / CPU 自动回退、混合队列取消、小丸参考两遍编码和黄色扩容结果。打包目录中的 EXE 通过同一智能流程、重启后历史重试及体积诊断检查，内置 VMAF / FFmpeg / FFprobe 可用。当前内置模型只适合本文说明的 SDR 抽样场景；没有对真实长片执行完整质量评分，也不承诺所有素材都能再缩小。

早期质量基线因 MKV / MP4 时间基准舍入造成帧对齐错误，已撤回旧分数并重测，见 QUALITY.md。自动选参现在按帧序号对齐并核验帧数，不使用旧评分结论。
