# v0.8.0 用途与参数搭配

日期：2026-11-09。此次调整以“先决定用途，再查看搭配”为核心。源文件始终保留，所有模式均在本机执行。

| 用途 | 默认搭配 | 可调整项 | 取舍 |
| --- | --- | --- | --- |
| 自动压缩 | CPU 多点试压；H.264 / H.265 随原片；复制音轨 | 细节要求、CPU / 显卡、素材类型、允许 H.265、容器 | 额外分析耗时；不合格则保留原片 |
| 手动调画质 | CPU / slow / H.265 10bit；录屏改 H.264 | 画质滑块、CPU / 显卡、编码、音频、分辨率、经典方案 | 大小不固定；不保证比原片小 |
| 指定大小 | CPU 两遍 / H.264 / AAC 128 kbps | 每个文件目标 MB、编码、音频、经典方案 | 目标近似；更小目标可能损失更多画质 |
| 快速压缩 | 自动显卡 / H.265 8bit / medium | 编码器、画质、H.264、混合并行 | 画质系数不能跨编码器等价比较 |
| 兼容播放 | MP4 / H.264 8bit / AAC / 显卡优先 | 画质、加速、分辨率、AAC 码率 | HEVC 转 H.264 可能增大，不保证所有设备播放 |

小丸经典参考是手动调画质或指定大小下面的编码方案，放在更多设置中。选择后固定 H.264、8bit、veryslow。它不与 GPU 叠加；两遍模式与恒定画质是互斥的码率控制方式。

每次切换用途会应用整套推荐参数，清除旧模式的静音、缩放、并行、体积目标等设置；素材类别可保留，兼容播放使用通用类别。右侧摘要显示实际搭配，参数可在该模式允许的范围内调整。“恢复推荐搭配”只恢复当前用途。升级保留已有有效手动参数，修正 CPU / 显卡与两遍模式等冲突。

混合并行对普通手动调画质、快速压缩和兼容播放提供，需两个及以上待处理视频，显卡和 CPU 各处理一个文件。单文件不会拆段。没有显卡或选择 CPU 时不启用混合并行。

## 公开项目对照与本项目的取舍

以下内容参考公开 README 和官方文档，独立实现交互和代码，没有导入这些项目的界面代码、图标、可执行文件或模型。对照不代表性能已达到或超过它们。

| 参考项目 | 已核实的设计 / 功能 | 凝影阁的应用 |
| --- | --- | --- |
| [HandBrake](https://github.com/HandBrake/HandBrake) / [预设说明](https://handbrake.fr/docs/en/latest/workflow/select-preset.html) | 一套预设包含面向设备或用途的多个设置 | 五个用途入口一次配齐参数，右侧显示输出摘要 |
| [HandBrake 画质说明](https://handbrake.fr/docs/en/latest/workflow/adjust-quality.html) | 恒定画质和编码参数需要理解相应取舍 | 用普通语言说明画质与大小，目标体积单独成为用途 |
| [ab-av1](https://github.com/alexheretic/ab-av1) | 采样搜索 CRF，报告质量与预计大小，再完整编码 | 延续已有试压评分，明确解释“保留原片”是正常结果 |
| [StaxRip](https://github.com/staxrip/staxrip) | 高度可配置的编码前端，提供逐步 Assistant | 常用搭配直接显示，经典参考及细项按需展开 |
| [Other Video Transcoding](https://github.com/lisamelton/other_video_transcoding) | 自动选取硬件编码器，适当时回退软件编码 | 显示实际编码器及回退规则，区分速度与质量用途 |
| [NotEnoughAV1Encodes](https://github.com/Alkl58/NotEnoughAV1Encodes) | 把视频切段并以多个 worker 编码后合并 | 明确本项目的混合并行是两个文件，并不宣称已有单片分段功能 |
| [LosslessCut](https://github.com/mifi/lossless-cut) | 无损剪切、轨道操作、重新封装，不必重编码 | 明确兼容转码与缩小体积的不同目标，不把转码称为无损操作 |

## 视觉与交互

使用 UI/UX Pro Max 的标签、反馈和状态指导，以及 frontend-design 的版式与视觉审查流程。数据库对 progressive disclosure 的首个匹配不适用，因此采用技能通用表单原则与上述产品对照来组织更多设置。

玉白 #fbfcf8 为操作面，青玉 #285f50 表示选择与执行，墨色 #203f38 为正文，灰绿 #52695e 为说明，边线 #c6d2c5。标题延用本地宋体/古风展示字体，控制项使用系统中文无衬线。山水仍作为远景，正文覆盖在清晰的浅色面板上。

桌面左侧保留导航，中间为用途、文件和结果，右侧为本次搭配。五个用途按钮均有名称、适用场景和选中标记；详细说明紧随选择更新。历史页面只显示记录，避免让人误以为右侧设置会更改历史成品。窄窗口缩减导航宽度，小屏纵向排列。键盘焦点、原生折叠控件和减少动态效果均保留。

## 验证方式

`pnpm test` 检查所有用途之间的切换、推荐参数组合、旧配置迁移和后端兼容约束。`pnpm test:modes` 验证五个入口、更多设置、无效大小阻止启动、实际 H.264 / AAC 输出、键盘焦点以及 390 / 960 / 1440 宽度布局。原有智能、显卡回退、混合队列、精细两遍和扩容诊断仍有单独的桌面测试。


## v0.8.0 操作说明

右侧先展示输出方案，再让用户选择画质取舍和 CPU / 显卡。画质快捷项使用「尽量保留细节 / 清晰且适中 / 文件更小」，手动滑块向右表示保留更多细节，文件通常也更大；不把编码器数值冒充画质百分比。速度改为「愿意花多少时间」，分辨率改为「画面尺寸」，技术名称保留在需要明确选择的格式与色深处。

自动压缩仍默认 CPU，用户可切换显卡。选自动显卡时，每个视频按实际输出编码解析设备；GPU 试压与完整输出使用同一套设置。GPU 试压不合适或完整编码失败时，CPU 重新试压评分，不沿用 GPU 的画质数值。指定显卡遇到错误保留原片。原片为 10bit 时，自动设备选择改用 CPU 保留色深，指定显卡则说明不支持。

历史记录的垃圾桶只删除对应记录；清空记录也不删除文件。不增加文件删除功能。正在处理任务时禁用删除，避免完成记录和手动管理冲突。
